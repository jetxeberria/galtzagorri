## Starting point

Facts checked on 2026-11-18:

- `template/Justfile` has `init: init-git install-hooks`. `init-git` runs `git init` unconditionally.
- galtzagorri's README says to run `just init install` after `copier copy`. The generated README does not mention `init`.
- `install` = `install-system install-user install-env`, and `install-env` already ends with `install-hooks`.
- Packaging is the `packaged` answer (PKG-1). lantoki and harness-harvest answer `true`; their `.copier-answers.yml` keeps `packaged: true`.
- `pdm build` cleans `dist/` before building, unless you pass `--no-clean`.
- `uv tool install` fails when the package declares no `[project.scripts]` ("No executables are provided").
- `lantoki sync repo .` asks once per machine which project sources apply (the selection is stored in the machine's manifest, lantoki INS-7). It exits with 1 on conflicts (lantoki CLI-1).

## Phase 2: the init recipes (`template/Justfile`)

```just
# Make this checkout ready to work, on a new machine too (idempotent)
init: init-git install install-tool-editable init-hook init-ai check
```

| Recipe | Behaviour |
|---|---|
| `init-git` | Skips with an `info` message when `git rev-parse --git-dir` succeeds; otherwise `git init` + `git add -A`. |
| `init-hook` | Runs `just init-project` when `just --show init-project` finds it, so only when `project.just` defines it; otherwise it prints that it is skipping. |
| `init-ai` | When `lantoki` is on `PATH`: `lantoki sync repo .`. Otherwise it warns with the two commands that install lantoki, and succeeds. |

The hook call can't be a just dependency: a missing recipe is an error in just. So it is a shebang recipe that test with `just --show`.

Naming: the template recipe is `init-hook`, and the recipe it calls is `init-project`, which the project defines. Giving both the same name would duplicate a recipe, which JUS-1 forbids.

## Risks

| Risk | Mitigation |
|---|---|
| `init` asks for sudo (`install-apt`) even when every package is installed | Accepted: `apt-get install` of installed packages changes nothing, and `init` is interactive by nature. Skipping apt when nothing is missing is possible later work. |
| `lantoki sync repo .` reports a conflict (for example a project that commits its own `AGENTS.md` while lantoki's repo-instructions source is selected) and `init` stops | Intended: the conflict is visible, and lantoki never overwrites it (PRI-5). Answer *no* for that source, or run `lantoki sync repo . --select`. |
| `init-ai` on a machine where lantoki is not installed yet | It warns and succeeds. Order on a new machine: clone lantoki, `just init` there (DEV-7), then `just init` in other projects. |

## Out of scope

- Installing lantoki from the template (cloning it) when it is missing.
- `gh auth login` and other per-user credentials.
